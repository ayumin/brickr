## 詰まった / 失敗したこと

### 1. Issue 添付画像が取得できず、同一コマンドを約 20 回リトライして停止（#173）

ロゴ差し替えタスクで、Issue に添付された PNG を Design Management API 経由で
取得しようとして 404 が返り、**まったく同じ curl コマンドを約 20 回繰り返して**
セッションが停止した。

**原因**: 添付ファイルは Design Management API のエンドポイントでは取得できず、
かつ 404 に対してリトライ以外の分岐がなかった。エージェントはバイナリ画像を
見ることもできない。

**次回どうするか**: 画像アセットの差し替えはエージェントに投げない。
先に人間がアセットをリポジトリにコミットし、Issue には
「`docs/images/logo.svg` に差し替え済みなので参照箇所を更新して」という形で
**リポジトリ内のパスを指定**して依頼する。

### 2. `glab mr create --description` へのインライン文字列でシェル展開事故（#171）

説明文をインラインで `--description "..."` に渡した結果、本文中のバッククォート
（`` `room-authorization-matrix.test.ts` `` など）がコマンド置換として解釈され、
`/bin/sh: 1: room-authorization-matrix.test.ts: not found` が多数出力された。

**原因**: ダブルクォート内のバッククォートはシェルが展開する。
`.agents/skills/glab/SKILL.md` にはクォート付き heredoc を使う指針があるが、
`--description` に**インラインで**渡す場合の危険性が明示されていなかった。

**次回どうするか**: MR 説明・Issue コメントは必ず一時ファイルに書き出してから
`--description "$(cat /tmp/mr-desc.md)"` で渡す。同日の #168 と #174 のセッションは
この方式で成功しており、こちらが正しいパターン。

### 3. MR テンプレートの探索が毎回失敗している

3 セッションすべてが `.gitlab/merge_request_templates` を探して存在せず、
`.gitlab` を列挙し直してから「テンプレートなし」と判断していた。

**原因**: MR テンプレートが未整備。

**次回どうするか**: `.gitlab/merge_request_templates/default.md` を用意する。
探索の無駄が消えるだけでなく、MR 説明の構成が人間・エージェント間で揃う。

### 4. Prisma 未初期化によるテスト失敗の切り分けに毎回コストがかかっている

`@prisma/client did not initialize yet` で 14〜16 のテストファイルがロードに失敗する。
エージェントは毎回これが自分の変更と無関係であることを確認する作業を行っている。
#171 のセッションでは「新規 2 ファイルの失敗も既存 14 件と同じ原因か」の検証に
往復が発生した。

**原因**: エージェント実行環境で `prisma generate` が走っていない。
かつ、この既知の状態がドキュメント化されていない。

**次回どうするか**: エージェント環境のセットアップに `prisma generate` を含める。
即座に対応できない場合は、最低限 `CLAUDE.md` に
「DB なし環境では N ファイルが Prisma 未初期化で fail する。これは既知で無関係」
と明記して切り分けコストを削る。

### 5. monorepo でサブディレクトリから git 操作して空振り

`cd apps/backend && git diff --stat HEAD` が空を返し、
リポジトリルートで再実行し直す往復が複数セッションで発生した。

**次回どうするか**: git 操作は常にリポジトリルートから実行する。
